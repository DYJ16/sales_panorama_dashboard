## 第 3 页：系统总体架构

### 页面标题

五层架构：数据源、分布式计算、指标服务、可视化展示、智能分析

### 页面核心内容

系统采用分层架构设计，每一层承担不同职责。SQL Server 负责保存销售事实数据和维度数据；Spark 负责将销售明细数据加工为经营指标；FastAPI 负责对外提供统一接口；前端大屏负责可视化展示；DeepSeek V4 负责生成智能经营分析结果。

### 页面结构内容

#### 1. 数据源层

SQL Server / AdventureWorksDW 提供销售事实表和维度表，是系统的数据事实来源。

#### 2. 分布式指标计算层

Spark Standalone 集群通过 JDBC 读取 SQL Server 数据，在 node1、node2、node3 上执行并行计算，输出 KPI、趋势、渠道、产品、区域和预警指标。

#### 3. 指标结果层

Spark 将计算结果输出为 JSON 文件，形成稳定的指标结果层，避免前端频繁触发复杂 SQL 查询。

#### 4. 接口服务层

FastAPI 读取 Spark 结果文件并提供 REST API，同时提供 DeepSeek V4 报告生成接口。

#### 5. 可视化与智能分析层

ECharts 负责图表呈现，DeepSeek V4 负责把指标转化为经营结论和管理建议。

### 页面视觉设计

使用纵向五层架构图，每层使用一个横向卡片。Spark 层需要用最醒目的蓝色或高亮边框，因为它是系统从传统 BI 升级为分布式系统的核心。DeepSeek V4 层可以用独立的 AI 标识增强智能分析感。

## 第 5 页：三节点分布式计算架构

### 页面标题

node1、node2、node3 如何构成 Spark 分布式指标计算集群

### 页面核心内容

系统使用 Spark Standalone 架构构建三节点分布式计算环境。node1 作为 Master 负责任务调度和资源管理，node1、node2、node3 作为 Worker 参与计算。销售指标计算任务提交后，会被拆分为多个 Stage 和 Task，由不同 Worker 上的 Executor 并行执行。

### 页面内容模块

#### node1

- 运行 Spark Master
- 负责接收 Spark 计算任务
- 负责管理 Worker 资源
- 负责调度 Executor 和 Task
- 同时也可以作为 Worker 参与计算

#### node2

- 运行 Spark Worker
- 接收 Master 分配的计算任务
- 执行销售指标计算中的部分 Partition
- 提升整体并行计算能力

#### node3

- 运行 Spark Worker
- 与 node2 一样承担 Executor 执行任务
- 承接产品排行、区域汇总、渠道聚合等分区计算
- 让系统具备横向扩展能力

### 分布式体现内容

- Spark Master 地址为 `spark://node1:7077`
- 任务不是本地单机执行，而是提交到 Spark 集群
- 销售数据被切分为多个 Partition
- 不同 Worker 并行处理不同 Partition
- 计算结果最终汇总输出到指标结果目录

### 系统运行时 Spark 的位置

在系统运行过程中，Spark 不直接面对浏览器用户，也不替代 FastAPI。它处在 SQL Server 与 FastAPI 之间，承担“经营指标预计算”的角色。

运行链路可以写成：

```text
SQL Server 明细数据
        ↓
PySpark 读取事实表和维度表
        ↓
Spark Master 调度任务
        ↓
Worker Executor 并行计算
        ↓
输出 JSON 指标结果
        ↓
FastAPI 读取结果并返回给前端
```

这样设计后，用户打开前端大屏时，接口读取的是 Spark 已经算好的指标结果，而不是每次刷新页面都重新执行复杂 SQL 聚合。

### 页面视觉设计

页面中央放 Spark Master，下面放三个 Worker 节点，使用箭头表示任务分发和结果汇总。node2 和 node3 要明确写成“参与并行计算”，避免观众误解为只有 node1 在工作。

### 建议图示

```text
                Spark Master
                  node1
                    |
       ┌────────────┼────────────┐
       ↓            ↓            ↓
 Worker node1   Worker node2   Worker node3
 Executor       Executor       Executor
       └────────────┼────────────┘
                    ↓
          Spark 指标结果 JSON
```

- Spark 启动脚本：`scripts/run_spark_job.sh`

## 第 6 页：Spark 分布式指标计算引擎

### 页面标题

Spark 分布式指标计算引擎：从销售明细到经营指标

### 页面核心内容

本系统中不要把 Spark 描述为普通的数据处理工具，而应定义为“Spark 分布式指标计算引擎”。它负责从 SQL Server 数据仓库读取销售明细和维度数据，完成事实数据整合、维度关联、多维聚合、排行计算、占比计算和异常识别，并输出前端和 AI 可直接使用的经营指标。

### Python / PySpark 设计

系统中的 Spark 逻辑由 Python 编写，核心文件是 `backend/spark_jobs/sales_spark_job.py`。这份脚本不是简单脚本，而是一个完整的指标计算任务，负责创建 SparkSession、读取 SQL Server 数据、构建销售宽表、计算经营指标，并把结果输出为 JSON。

Python 侧的 Spark 设计可以拆成 5 个部分：

#### 1. SparkSession 创建

通过 `spark_config.py` 统一配置 Spark 应用名称、Master 地址、JDBC 驱动和运行参数。SparkSession 是 PySpark 程序的入口，后续所有 DataFrame 读取、转换和聚合都基于它执行。

页面可展示内容：

```text
SparkSession
应用名称：EnterpriseSalesPanoramaSpark
Master：spark://node1:7077
运行模式：Standalone Cluster
```

#### 2. SQL Server 数据读取

通过 JDBC 读取 SQL Server 表，将数据库中的事实表和维度表加载为 Spark DataFrame。DataFrame 会被 Spark 划分为 Partition，后续可以由多个 Executor 并行处理。

页面可展示内容：

```text
SQL Server Table → Spark DataFrame → Partition
```

#### 3. 销售宽表构建

Python 中先把 Internet 销售和 Reseller 销售进行字段标准化，再合并为统一销售事实数据集，之后关联日期、产品、客户、地理维度，形成销售分析宽表。

这一步的作用是把原始业务表转换为面向分析的统一数据模型。

#### 4. 指标函数模块化

PySpark 代码将不同指标拆分为独立函数，例如 KPI、趋势、渠道、产品、区域和预警。每个函数只负责一种指标计算，结构清晰，方便后续新增指标。

页面可展示内容：

```text
compute_kpis()          → KPI 总览
compute_trend()         → 销售趋势
compute_channels()      → 渠道结构
compute_top_products()  → 产品排行
compute_geo()           → 区域分析
compute_alerts()        → 风险预警
```

#### 5. 指标结果输出

每个计算函数最终输出对应 JSON 文件。FastAPI 不需要理解 Spark 内部计算过程，只需要读取这些标准结果文件并提供接口。

### Spark 输入数据

Spark 通过 JDBC 读取 AdventureWorksDW 中的关键表：

- `FactInternetSales`：互联网销售事实表
- `FactResellerSales`：经销商销售事实表
- `DimDate`：日期维度
- `DimProduct`：产品维度
- `DimCustomer`：客户维度
- `DimGeography`：地理区域维度

### Spark 计算流程

#### 1. 销售事实统一

将 Internet 销售和 Reseller 销售合并为统一销售数据集，统一销售金额、订单编号、产品 Key、客户 Key、日期 Key 和销售渠道字段。

#### 2. 销售宽表构建

将销售事实表与日期、产品、客户、地理维度进行关联，形成可直接分析的销售宽表。

#### 3. 多维聚合计算

基于 Spark DataFrame API 执行 KPI 汇总、月度趋势、渠道聚合、产品排行、区域汇总等计算。

#### 4. 经营规则识别

通过规则计算识别销售回落、渠道结构不均衡、头部产品依赖、区域销售波动等经营风险。

#### 5. 指标结果沉淀

将最终结果输出为 JSON 指标文件，供 FastAPI、前端和 DeepSeek V4 复用。

### 与非分布式系统的对比

如果不使用 Spark，传统系统通常由 FastAPI 直接查询 SQL Server，每个接口都执行一次聚合 SQL。这样在数据量增加、指标变复杂、用户频繁刷新时，数据库和接口服务会承受较大压力。

引入 Spark 后，复杂指标计算从 Web 接口中拆出来，由分布式计算引擎统一完成。FastAPI 只负责读取结果和返回接口，系统职责更清晰，计算能力也可以通过增加 Worker 节点扩展。

| 对比项 | 非分布式系统 | 本系统 Spark 方案 |
| --- | --- | --- |
| 指标计算位置 | FastAPI 或 SQL Server 实时计算 | Spark 集群统一预计算 |
| 计算资源 | 单机数据库或 Web 后端 | node1、node2、node3 多节点并行 |
| 页面刷新压力 | 每次可能触发复杂 SQL | 读取已生成的 JSON 指标结果 |
| 扩展方式 | 优化 SQL 或提升单机配置 | 增加 Spark Worker 节点 |
| 指标复用 | 各接口重复查询 | 指标结果统一沉淀 |
| AI 分析输入 | 可能直接依赖原始查询结果 | 使用 Spark 生成的结构化指标 |

### 系统提升效果

- 后端接口更轻量：FastAPI 从“计算接口”变成“指标服务接口”。
- 数据库压力更低：复杂聚合由 Spark 承担，SQL Server 更专注于数据存储。
- 计算能力更强：Worker 节点可以并行执行分区任务。
- 指标口径更统一：前端和 DeepSeek V4 使用同一份 Spark 结果。
- 系统更适合扩展：后续新增销售预测、客户分群、库存风险等指标时，可以继续放入 Spark 计算层。

## 第 7 页：核心经营指标体系

### 页面标题

经营指标体系：从销售规模到风险预警的多维分析

### 页面核心内容

系统围绕企业销售管理构建了完整指标体系。指标不是零散展示，而是按照管理层关注路径组织：先看整体规模，再看趋势变化，然后分析渠道、产品和区域，最后通过 AI 形成经营判断。

### 指标体系内容

#### 1. KPI 总览指标

- 总销售额
- 总订单量
- 客户数量
- 产品数量
- 平均客单价

用途：快速判断企业整体销售规模和经营状态。

#### 2. 销售趋势指标

- 月度销售额
- 月度订单量
- 销售峰值月份
- 销售低谷月份
- 环比变化趋势

用途：识别销售增长、回落和波动周期。

#### 3. 渠道结构指标

- Internet 渠道销售额
- Reseller 渠道销售额
- 渠道订单量
- 渠道销售占比
- 渠道客单价

用途：判断渠道结构是否均衡，识别渠道依赖风险。

#### 4. 产品贡献指标

- Top 产品销售排行
- 产品销售贡献率
- 产品订单贡献
- 产品线表现

用途：识别核心产品、高贡献产品和头部产品集中风险。

#### 5. 区域经营指标

- 国家销售额
- 地区销售额
- 城市销售额
- 区域订单量

用途：发现核心市场、潜力市场和区域销售差异。

#### 6. 风险预警指标

- 销售回落预警
- 渠道占比异常
- 头部产品依赖
- 区域销售波动

用途：将数据变化转化为管理层需要关注的风险项。

### 页面视觉设计

## 第 9 页：DeepSeek V4 智能经营诊断

### 页面标题

DeepSeek V4：从指标展示到经营诊断

### 页面核心内容

DeepSeek V4 是系统智能分析能力的核心。Spark 负责把数据算成指标，DeepSeek V4 负责把指标解释成经营判断。两者形成上下游关系：Spark 提供可信的结构化指标，DeepSeek V4 基于这些指标生成管理层可直接阅读的经营分析报告。

### DeepSeek V4 输入内容

- KPI 总览数据
- 月度销售趋势
- 渠道销售结构
- Top 产品贡献
- 区域销售表现
- Spark 识别出的异常预警

### DeepSeek V4 输出内容

#### 1. 总体经营概览

概括当前销售规模、订单情况和整体经营状态。

#### 2. 趋势判断

判断销售增长、回落、波动周期和需要关注的月份。

#### 3. 渠道分析

分析 Internet 与 Reseller 渠道结构是否均衡，是否存在渠道依赖。

#### 4. 产品分析

识别高贡献产品、头部产品依赖和产品结构风险。

#### 5. 区域分析

分析重点区域和潜力区域，辅助市场资源分配。

#### 6. 管理建议

输出面向经营管理的行动建议，例如关注库存、优化渠道结构、跟进重点区域等。

### 页面视觉设计

建议页面左侧展示 Spark 指标输入卡片，右侧展示 DeepSeek V4 生成的经营报告卡片，中间用箭头连接，表达“指标到决策”的转换。

### 对应系统模块

- AI 请求模块：`backend/ai/deepseek_v4_report.py`
- Prompt 模板：`backend/ai/prompt_templates.py`
- AI 服务：`backend/services/ai_report_service.py`
- 前端展示区：`AI 经营分析中心`

## 第 10 页：Harness工程与报告质量控制

### 页面标题

Harness 工程：让 AI 输出专业、克制、可落地

### 页面核心内容

系统接入 DeepSeek V4 不是简单发送一句问题，而是通过 Harness工程控制报告质量。Prompt 要求模型必须基于 Spark 指标进行分析，不能脱离数据泛泛而谈，不能编造不存在的指标，输出内容要适合企业销售经营场景。

### Prompt 设计原则

#### 1. 数据约束

报告必须基于输入的 KPI、趋势、渠道、产品、区域和预警数据生成，不能生成与数据无关的判断。

#### 2. 业务语言

输出内容要使用经营分析语言，例如“渠道依赖”“头部产品集中”“销售回落”“区域机会”“管理动作”，避免普通聊天式表达。

#### 3. 结构清晰

报告按经营概览、趋势分析、渠道分析、产品分析、区域分析、风险预警、管理建议组织。

#### 4. 长度可控

报告内容控制在前端大屏可展示的范围内，不输出过长段落，不使用复杂表格。

#### 5. 行动导向

报告不只解释数据，还要给出下一步管理建议。

### 报告生成流程

```text
读取 Spark 指标结果
        ↓
组装经营分析 Prompt
        ↓
调用 DeepSeek V4
        ↓
生成经营诊断报告
        ↓
保存并展示到前端
```

### 页面视觉设计

页面可以采用“质量控制清单”的形式，用 5 个勾选项展示 Prompt 约束：基于数据、业务语言、结构清晰、长度可控、行动导向。

### 对应系统文件

- `backend/ai/prompt_templates.py`
- `backend/ai/deepseek_v4_report.py`
- `backend/services/ai_report_service.py`

## 第 12 页：系统核心价值总结

### 页面标题

Spark 与 DeepSeek V4 构成系统核心竞争力

### 页面核心内容

本系统的核心价值不是单个页面，也不是单个图表，而是把企业销售数据通过分布式计算和 AI 分析形成可执行的经营决策闭环。

### Spark 的核心价值

Spark 作为分布式指标计算引擎，承担销售经营指标的统一加工、并行聚合和结果沉淀。它让系统摆脱传统大屏对实时 SQL 聚合的依赖，使销售分析能够面向更大数据量、更复杂指标和多节点计算环境扩展。

Spark 在系统中的价值包括：

- 统一加工 Internet 与 Reseller 销售数据
- 构建销售分析宽表
- 并行计算 KPI、趋势、渠道、产品和区域指标
- 识别经营风险和异常信号
- 输出可复用的指标结果文件
- 支撑前端和 AI 的统一数据基础

### 相比普通销售大屏的提升

普通销售大屏通常把计算逻辑放在数据库 SQL 或后端接口中，页面请求越多，数据库和后端压力越大。Spark AI 企业销售决策系统将销售指标计算前移到 Spark 分布式指标计算引擎中，由 PySpark 统一完成数据读取、宽表构建、聚合计算、风险识别和结果输出。

这种设计带来的提升包括：

- 计算架构更专业：从接口实时查询升级为独立指标计算引擎。
- 分布式能力更明确：node1 调度，node2、node3 参与并行计算。
- 指标结果更稳定：前端读取已沉淀的 JSON 指标，而不是反复执行复杂 SQL。
- 业务扩展更容易：新增指标时主要扩展 PySpark 计算函数，不需要重构整个前端。
- AI 分析更可靠：DeepSeek V4 使用统一的 Spark 指标作为输入，报告口径更一致。

### DeepSeek V4 的核心价值

DeepSeek V4 作为智能经营诊断引擎，承担指标解释、风险判断和管理建议生成。它让系统从“展示数据”进一步升级为“辅助决策”。

DeepSeek V4 在系统中的价值包括：

- 基于 Spark 指标生成经营诊断
- 将复杂数据转化为管理层可读语言
- 识别渠道、产品、区域中的经营风险
- 输出下一步管理建议
- 降低人工解读图表的成本

### 系统最终价值

```text
数据层：SQL Server 提供销售事实
计算层：Spark 提供分布式指标计算
服务层：FastAPI 提供统一接口
展示层：ECharts 提供经营可视化
智能层：DeepSeek V4 提供决策建议
```

### 页面视觉设计

最后一页建议使用“价值闭环图”。中心写“Spark AI 企业销售决策系统”，外圈五个能力点：数据可信、计算高效、展示直观、诊断智能、决策可执行。

### 收束内容

Spark AI 企业销售决策系统实现了从传统销售 BI 到智能销售决策平台的升级。系统既能通过 Spark 展示分布式计算能力，也能通过 DeepSeek V4 展示 AI 经营分析能力，最终为企业销售管理提供可视化、智能化、可扩展的决策支持。
